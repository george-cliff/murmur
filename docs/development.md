## Python model pipeline

### Requirements

- A Python environment capable of installing `requirements.txt`.
- The `ff1010bird`, `warblrb10k`, and `BirdVox-DCASE-20k` development datasets from the [DCASE 2018 Bird Audio Detection task](https://dcase.community/challenge2018/task-bird-audio-detection). Download them from their original source; do not add raw or processed dataset files to the repository.
- Enough local storage for extracted audio and precomputed spectrogram arrays.
- Suitable CPU or GPU resources for the intended training run; no universal hardware requirement has been established.

### Current command path

1. Create and activate a Python virtual environment.
2. Install the packages in `requirements.txt`.
3. Run `python -m tools.setup` to create the ignored data, model, and log directories.
4. Run `python -m tools.process_data.process_data` to extract data, create manifests, and generate spectrograms.
5. Optionally run `python -m tools.benchmark_workers` on the current machine before a larger training run.
6. Run `python -m sparrowhawk` to execute training, export, quantisation, and threshold evaluation as separate subprocess stages.

The exact local placement steps still need to be converted into a reproducible guide. That guide should link to the original downloads and explain the expected directory layout without copying or redistributing the datasets.

## Rust desktop runner

### Required local files

- A generated quantised Sparrowhawk ONNX model.
- The saved Sparrowhawk deployment threshold.
- A Perch v2 ONNX model and matching label list.
- Representative WAV files in the development paths expected by the runner.
- A Rust toolchain compatible with the crate's current edition and dependencies.

### Current command

```text
cargo run
```

Treat this as a development entry point. It uses fixed inputs and development configuration; it is not a service, field-device image, or packaged desktop application.

## Verification already represented in the code

- ONNX export compares PyTorch and ONNX Runtime outputs for numerical closeness.
- Quantisation evaluates float and quantised models on the recorded validation split.
- Calibration sampling is deterministic and kept outside that validation split.
- Sequence numbers prevent duplicate detection inserts when the fixed input set is rerun.
- Training records its validation rows so later export and threshold stages can reuse the same split.
